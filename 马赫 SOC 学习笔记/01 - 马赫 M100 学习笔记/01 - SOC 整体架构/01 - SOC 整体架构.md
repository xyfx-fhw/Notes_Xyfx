# 1 SOC 顶层架构

![[M100 SoC 顶层架构.excalidraw | 1000]]

M100 采用典型的异构 SoC 架构：**通用 CPU 负责控制与调度，NPU 负责 AI 计算，多媒体引擎负责感知输入**，再由片上互联与 LPDDR5X 把所有主设备连成一个整体。下面将顶层框图中的各子系统逐一展开，说明每个模块的作用。

## [[01 - NPU 架构|1.1 NPU 子系统（NPU、NPU Scheduler）]]

NPU 子系统是整颗芯片的 AI 算力核心，由计算引擎和调度器两部分组成。

**NPU**：专用神经网络计算引擎，以矩阵乘、卷积、激活、量化/反量化等张量运算为加速对象，同等功耗下的算力远高于通用 CPU。其内部通常按 Cluster → Tile 的层级组织，每个 Tile 集成计算单元与本地 SRAM，通过增加 Cluster / Tile 数量线性扩展算力（内部结构详见 NPU 架构笔记中的 Cluster ×14、Tile ×4、HMEM 等）。

**NPU Scheduler**：NPU 的硬件/固件级"调度中心"。负责接收 CPU 提交的任务描述与命令队列，把计算任务拆分、编排到空闲的 Cluster / Tile 上执行，并处理任务间的数据依赖、同步（barrier）与中断上报。有了 Scheduler，CPU 只需"提交任务、等完成通知"，不必逐条管理硬件细节，这是降低 NPU 编程开销、提高算力利用率的关键。

## 1.2 通用处理器 / CPU 子系统（24-Core CPU Cluster）

**24-Core CPU Cluster**：运行操作系统与 RTOS 的通用算力，承担全部串行控制逻辑——系统启动、驱动与资源管理、模型加载、数据前后处理、向 NPU 提交任务、协议栈与业务应用等。24 个核心为多线程前后处理和多任务并发提供余量。在异构分工中遵循"CPU 管控制、NPU 管计算"的原则：CPU 做分支密集的控制流，NPU 做数据密集的并行计算，二者通过共享内存与中断协作。

## 1.3 多媒体子系统 / 视觉处理管线（ISP、VPU、MIPI-CSI）

三个模块串成完整的视觉感知管线：传感器 → MIPI-CSI → ISP → VPU / NPU。

**MIPI-CSI**：MIPI 相机串行接口，负责对接摄像头传感器，把高速串行图像数据（RAW）接收并解串，是视觉数据的入口。

**ISP**：图像信号处理器，对 RAW 数据做去马赛克、自动曝光、自动白平衡、降噪、HDR 合成、色彩校正等一系列画质处理，输出可直接供 NPU 推理或编码保存的图像。

**VPU**：视频处理/编解码单元，硬件加速 H.264/H.265 等标准的视频解码与编码，用于多路视频流接入、录像与转码，避免视频处理占用 CPU/NPU 算力。

## 1.4 内存子系统（LPDDR5X ×8）

**LPDDR5X ×8**：低功耗、高带宽内存，×8 为位宽/通道配置，多路并行提供数百 GB/s 级带宽。对 NPU 而言，"内存墙"往往比峰值算力更先成为瓶颈——推理时权重与激活的搬运速度直接决定实际吞吐，因此高带宽 LPDDR5X 是"喂饱"计算单元的前提。同时，统一的物理内存让 CPU、NPU、多媒体引擎可以零拷贝共享同一份数据（对应架构图中的"通过 DDR 共享数据"链路），省去重复拷贝与同步开销。

## 1.5 片上互联（Coherent Interconnect & LLC）

**Coherent Interconnect**：片上互联网络（NoC），把 CPU 集群、NPU、DMA、多媒体引擎等所有主设备连接起来，并在硬件层面维护缓存一致性——一个主设备修改的数据，其他主设备无需手动 flush/invalidate 即可读到新值，大幅简化异构编程的正确性负担。

**LLC**：挂在互联上的共享末级缓存，缓存各主设备共用的热数据，减少对 DDR 的访问压力、降低平均延迟，是提升有效带宽利用率的关键结构。

## 1.6 存储接口（UFS、QSPI）

**QSPI**：四线 SPI 接口，对接 NOR Flash，通常存放 Bootloader 与底层固件，支持 XIP（片内直接执行），是启动链的第一级外部存储。

**UFS**：高速闪存接口（eMMC 的替代者），存放操作系统、文件系统、AI 模型与业务数据，顺序读写性能远高于 eMMC，直接决定开机速度与模型加载速度。

典型启动顺序：片内 BootROM → QSPI NOR 中的 Bootloader → UFS 中的系统与模型。

## 1.7 高速接口（USB 3.1、eUSB 2.0、10G Eth ×2）

**USB 3.1**：对外高速通用接口，连接外置存储、相机、扩展模块等。

**eUSB 2.0**：嵌入式 USB 2.0，电气规格面向板级嵌入场景，成本更低、布线更简单，用于中低速外设或内部模块连接。

**10G Eth ×2**：双路万兆以太网，是边缘设备的网络动脉——多路高清视频流接入、向平台/云端回传，部分部署中还用于节点间互联；双口可做链路聚合或冗余容错。

## 1.8 低速接口（Low Speed I/O）

**Low Speed I/O**：控制类外设的集合，通常包括 UART、I2C、SPI、CAN、GPIO、PWM、看门狗等。带宽需求低，但数量与可靠性关键，用于连接传感器、执行器、指示灯、串口设备以及调试串口，是嵌入式系统的"毛细血管"。

## 1.9 系统控制 IP / 平台基础设施（PMU、CRU、Security、FSI）

**PMU**：电源管理单元，划分电源域、管理休眠/唤醒状态，配合软件做 DVFS（动态电压频率调节），是功耗控制的核心。

**CRU**：时钟与复位单元，产生并分配全片时钟、管理各模块复位时序，是全片正常工作的"心跳"。

**Security**：硬件安全子系统——安全启动链、对称/非对称加解密加速、真随机数、密钥 OTP 存储与安全隔离域，保证模型与数据不被窃取、系统不被篡改。

**FSI**：功能安全岛（Functional Safety Island），独立于主系统的安全监控单元，负责系统健康管理、故障检测/收集/上报与安全状态控制，为主系统异常时的降级处理兜底，是功能安全场景的硬件基础。

## 1.10 调试与可追溯子系统（Debug & Trace）

**Debug & Trace**：提供开发期与现场问题的可观测性。包括 JTAG/调试访问通道（对应架构图中的"访问 Debug 地址"）、硬件 trace 单元（指令流、总线事务、时间戳记录）与性能计数器。可以在不打断系统运行的情况下观察 CPU/NPU 的实际行为，是定位性能瓶颈、偶发故障与启动问题的关键手段。
